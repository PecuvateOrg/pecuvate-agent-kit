# Templates Workspace

Scaffold content generated by the MWP skills when initialising a new project. Templates define the starting shape of each MWP file; skills populate them with project-specific content rather than leaving placeholders.

## What Lives Here

- AGENTS.md.template: starter canonical Layer 0 covering all seven components — routing only
- CLAUDE.md: none; projects have no `CLAUDE.md`
- NON-NEGOTIABLES.md.template: starter rules file, forced open by AGENTS.md's Self-Reference line — see spec/layers.md § NON-NEGOTIABLES.md
- agent-roles.md.template: starter role registry for agent responsibilities and boundaries
- CONTEXT.md.template: starter workspace CONTEXT.md
- skills.md.template: starter skills catalogue, pointing at the workspace skill index for shared skills
- README.md.template: starter human-facing README
- memory.md.template: starter memory.md

`spec/file-set.md` requires ten leaf files; nine are templated here. **`DEVLOG.md`
has no template** — it is seeded with a single dated entry at scaffold time, and its
format rule lives in `spec/session-memory.md`.

**This is the only template source.** A workspace documentation guide previously
carried its own bodies for `agent-roles.md`, `AGENTS.md`, `skills.md` and `memory.md`;
two had diverged from the copies here, and the `init-mwp-*` skills were generating
from the poorer set. Reconciled 2026-09-10 — that guide now holds practice only.

## AGENTS.md-first scaffolding

Every project uses this layout ([the spec](../spec/layers.md#cross-model-adapters)): generate
`AGENTS.md` from `AGENTS.md.template`, and create no `CLAUDE.md` or `GEMINI.md`.

## Design Principles

- Templates are guides, not fill-in-the-blank forms; the init-mwp skill reads them and generates contextually accurate content, not placeholder text
- Every section in a template must map to a component defined in `spec/` — see `spec/CONTEXT.md`, and `spec/file-set.md` for which files exist at all
- Templates should reflect the framework's own bounds: the AGENTS.md template is filtered by the Reasoning Test (`spec/layers.md`) — routing only, no fixed line target — and the CONTEXT.md template targets ~100 lines, within its 150-line ceiling
- Annotate each section with a comment explaining what belongs there and what the sizing rationale is

## Constraints

- Do not add sections not covered by `spec/` without updating the spec first. The spec changes first, always — a template ahead of the spec is a fork
- Template comments are for the skill to read; strip them from generated output
